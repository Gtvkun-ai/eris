TỔNG QUAN PROJECT ERIS
======================

Cập nhật: 2026-05-27
Mã hóa: UTF-8




Kết luận ngắn: các chức năng mới làm ERIS biết giữ mục tiêu, phục hồi phiên, nhận ra user đang hiện diện, hiểu ý nghĩa của tín hiệu thay vì đọc lại telemetry, và quyết định nói/im lặng có kiểm soát hơn. Đây là bước nâng từ "trả lời theo lượt" sang "có nhịp sống runtime giữa các lượt".

ERIS hiện tại là một hệ lai giữa thân thể hiển thị và nhận thức runtime:

- Godot + C#: phần "body". Nó hiển thị Monika, bubble nói, chat panel, context menu, animation, âm thanh và chuyển động vật lý trên màn hình.
- Python: phần "cognition/runtime". Nó đọc telemetry, chụp/nén thông tin màn hình khi cần, giữ memory, tính nội trạng, chọn lúc nói/im lặng, gọi LLM, parse kết quả, enforce guard, thực thi action và gửi decision về body.
- UDP: dây thần kinh giữa Godot và Python. Godot nhận decision ở cổng 4242, Python nhận chat/event ở cổng 4243.
- LLM: có thể chạy local llama-server với GGUF, hoặc remote cognition API. Hiện tại remote API mặc định được bật; local GGUF vẫn có thể dùng cho style rewrite và vision facts.
- Parser/Ti/Se/Evidence/AttentionSalience/WorkingMemory/MeaningLayer/SpeechCore/Personality/Memory/SessionRitual/MicroPolicy: các lớp neo ERIS vào bằng chứng, biến fact thô thành ý nghĩa có kiểm soát, tránh overclaim, tránh nói quá điều mình biết, giữ nhịp riêng và giữ liên tục giữa các turn/session.

Tóm tắt ngắn:
Godot là thân. Python là hệ thần kinh và cognition. UDP là dây nối. Model sinh câu và ý đồ. Parser, Ti, Se, Evidence, AttentionSalience, WorkingMemory, MeaningLayer, PersonalityLens, memory, speech_core, session_ritual, micro_policy và action_planner biến output đó thành hành vi có giới hạn, có bằng chứng, có nhịp riêng.


0. Thiết Lập Nhanh (Godot + Python)
-------------------------------

Cách chạy tối thiểu:
- Mở Godot, chạy scene `body/UdpListener.tscn`.
- Nếu `AutoStartVision` bật, Godot sẽ khởi động `src/vision.py`.
- Nếu tắt, chạy thủ công: `python src/vision.py` (hoặc `python src/vision.py <duong_dan_model.gguf>`).

Khi cần model local:
- Bắt buộc có `model.gguf` nếu `ERIS_REMOTE_API_ENABLED=0` hoặc `ERIS_LOCAL_STYLE_REWRITE_ENABLED=1`.
- Có thể đặt đường dẫn bằng `GGUF_MODEL_PATH`.

Kết nối mặc định:
- UDP: quyết định `4242`, event/chat `4243`.
- llama-server (local): mặc định `http://127.0.0.1:8080/v1` nếu dùng local GGUF.


1. Body Godot / C#
------------------

`project.godot`
- Cấu hình Godot project.
- Scene khởi động là `body/UdpListener.tscn`.
- Bật C#/.NET và các setting nền của app.

`Eris.csproj`, `Eris.sln`
- Project .NET cho script Godot.
- Target hiện dùng là `net8.0`.
- Các file `.old` là dấu vết cấu hình cũ.

`body/UdpListener.tscn`
- Scene gốc của body.
- Chứa `CanvasLayer`, chat panel, context menu, node nhân vật, sprite Monika, bubble text.
- Gắn script `body/UdpListener.cs`.
- Context menu hiện có thêm nút touch/grab để vào chế độ kéo nhân vật, bên cạnh chat, force speak và close.

`body/UdpListener.cs`
- File trung tâm bên Godot.
- Bind UDP port `4242` để nhận JSON decision từ Python.
- Gửi event về Python qua port `4243`: `chat_start`, `chat`, `chat_end`, `force_speak`.
- Delegate việc khởi động/dừng `src/vision.py` và `llama-server.exe` sang `ErisProcessManager`.
- Export các cấu hình runtime: Python executable, vision script, llama-server path, model path, mmproj path, remote cognition API, local style rewrite và thông tin provider/model.
- Parse payload gồm text, intent, animation, direction, target, motion intent, system action và action input.
- Parse thêm `should_speak` để không hiện bubble khi cognition chủ động im lặng, và parse `body_bias` để truyền trạng thái nền xuống `LocalBodyAutonomy`.
- Nếu payload không phải JSON mà là plain text, fallback về hiện text thô thay vì luôn báo lỗi đường truyền.
- Hiển thị bubble nói với typewriter effect.
- Quản lý chat panel, character context menu, touch/grab mode, animation, sound, body autonomy và payload parser.
- Nối `LocalBodyAutonomy` vào `_Process()`: khi body không bị kéo và motion không bận, autonomy có thể tự chọn đi, đứng, đọc, leo, lùi về anchor hoặc ngồi lại.
- Có cơ chế kéo/thả nhân vật: touch mode được bật từ context menu, click giữ để kéo, thả ra sẽ tính vận tốc chuột thành impulse ném cho `MotionController`.
- Khi đang kéo, body bị clamp trong viewport; khi bắt đầu kéo dùng pose `air_swing_l/r`, khi thả thì ghi nhận rough handling để tăng overload/solitude trong body autonomy.
- Remote motion từ cognition hiện bị khóa sau cờ `EnableLegacyRemoteMotionCommands`; mặc định body chỉ nhận speech + bias, tránh cognition override mọi chuyển động cục bộ.
- Chuẩn hóa animation model hay gọi sai, ví dụ `walk`/`run` -> `stand_walk`.
- Vẫn còn khá dày bên C#, nhưng phần process/service lifecycle đã được tách khỏi file này.
- Lưu ý bảo mật: đang có API key hardcoded trong `DefaultRemoteApiKey`.

`body/ErisProcessManager.cs`
- Tách lifecycle service khỏi `UdpListener.cs`.
- Chứa `ErisServiceConfig`: Python executable, script path, llama-server path, model/mmproj path, remote API, local style rewrite, local vision, context size và provider/model.
- `StartVision()` resolve path project, kiểm tra `vision.py`, chỉ boot một process nếu chưa chạy, và tự đảm bảo llama-server sẵn sàng khi local style rewrite hoặc local vision cần server.
- Spawn `vision.py` với `UseShellExecute=false`, `CreateNoWindow=true`, stdout/stderr redirect, `StandardOutputEncoding` và `StandardErrorEncoding` đều là UTF-8.
- Inject env cho Python: `PYTHONUTF8`, `PYTHONIOENCODING`, `PYTHONUNBUFFERED`, `LLAMA_SERVER_*`, `GGUF_MODEL_PATH`, `ERIS_N_CTX`, remote API vars, `GEMINI_API_KEY`, `ERIS_LOCAL_STYLE_REWRITE_ENABLED`, `ERIS_LOCAL_VISION_FACTS`.
- `StartLlamaServer()` kiểm tra port trước, build args gồm model, mmproj khi bật vision, context, GPU layers, host/port, `--no-warmup`, `--jinja`, `--reasoning-format deepseek`, `--cache-ram 1024` nếu chưa override, và flash attention.
- Có `ToggleVision()`, `ToggleLlamaServer()`, `StopAll()` và `StopProcess()` kill process tree sạch hơn khi tắt.
- Lọc stdout/stderr: chỉ in các dòng init/shutdown/loop/parse/LLM/vision/chat/raw/error đáng chú ý; traceback stderr được giữ theo state `_visionTracebackActive` để không mất phần stack trace.

`body/LocalBodyAutonomy.cs`
- File mới cho tự chủ thân thể cục bộ bên Godot.
- Chứa `BodyBias`: bias nhận từ cognition gồm `continuity_anxiety`, `curiosity`, `overload`, `solitude`, `focus_kind`, `preferred_anchor`.
- Chứa `BodyAutonomyContext`: snapshot nhẹ của body gồm vị trí, kích thước màn hình, action hiện tại, motion busy, chat visible và trạng thái đậu trên trần.
- Chứa `BodyAutonomyDecision`: quyết định action + `MotionCommand` + optional speech.
- `LocalBodyAutonomy` giữ các nhu cầu nội bộ: continuity, meaning, solitude integrity, quiet attachment, overload.
- Bias từ Python được blend dần thay vì thay thế đột ngột, giúp body không đổi hành vi quá gắt giữa các decision.
- Có bộ tension nhỏ: dissolution, noise identity, silent erasure. Các tension này dùng để chọn hành vi khi body im lâu, cognition im lâu, hoặc overload cao.
- Chọn hành vi theo score và cooldown:
  - `ReturnToAnchor`: đi về anchor mà cognition/body đang ưu tiên.
  - `ReadQuietly`: đứng đọc yên khi cần meaning hoặc solitude.
  - `ObserveCode`: nghiêng về phía code khi focus code và curiosity cao.
  - `ClimbWall`: leo lên mép/trần khi curiosity/restlessness đủ cao.
  - `DropFromCeiling`: rơi khỏi trần khi đậu lâu hoặc cần đổi nhịp.
  - `Withdraw`: lùi về góc phải dưới khi overload/solitude cao.
  - `DormantSit`: ngồi lại khi idle dài và cần continuity nhẹ.
  - `QuietObserve`: không làm gì nếu score chưa đủ.
- Có cooldown riêng cho từng action để body không lặp một hành vi liên tục.
- Anchor chính hiện là `chat_near`, `code_side`, `bottom_right`; được map thành X ratio trên màn hình.
- Ghi nhận tương tác user bằng `RecordUserInteraction()` và `RecordRoughHandling()` để cập nhật nhu cầu cục bộ.

`body/MotionController.cs`
- Lớp tách riêng cho chuyển động body.
- Nhận `MotionCommand` và quyết định đi, đứng, quay mặt, rơi, leo tường, lên mép, giữ trên mép.
- Quản lý gravity, tốc độ, hướng sprite, bubble flip và va chạm cạnh màn hình.
- Hiểu các intent chính: `walk`, `walk_to`, `face`, `pose`, `climb_loop`, `climb_to_top`, `drop`, `throw`.
- `MotionCommand` có thêm `impulseX`, `impulseY`, `clingChance` để hỗ trợ ném body bằng chuột.
- Thêm velocity ngang `_velocityX`, trạng thái `IsWalking`, `IsClimbing`, `IsTopPerched`, `IsThrown`, `IsBusy` cho autonomy biết lúc nào được phép chen vào.
- Khi `throw`, body dùng pose `air_swing_l/r`, rơi theo impulse, giảm dần vận tốc ngang và có thể bám tường nếu va cạnh màn hình với xác suất `clingChance`.
- Khi rơi bằng `air_swing_l/r`, animation giữ đúng pose treo thay vì luôn đổi về `air`.
- Đây là hướng tách đúng: cognition không còn phải tự điều khiển pixel trực tiếp trong `UdpListener`.

`asset/Resource/Monika.tscn`
- Định nghĩa `AnimatedSprite2D` và SpriteFrames.
- Map các animation như `stand`, `stand_walk`, `read`, `sleep`, `sad`, `food`, `affection`, `climb`, `climb_top`, `hop`, `jump`, `air`, `sit`.

`asset/Monika/*.png`
- Frame nhân vật.
- Các nhóm chính: đứng/đi/idle, đọc/ngủ/buồn/ăn/affection, leo tường/lên mép, nhảy/rơi/đu, clone/divide/shime/sit.

`asset/Monika/sound/*.wav`
- Âm thanh gắn với animation: bước chân, nhảy, va chạm, vui, ngủ, bị đau, pop.
- `UdpListener.cs` random sound theo map animation.

`asset/icon/*.png`, `asset/Resource/*.tres`
- Icon/chat/point resource cho UI Godot.

`*.import`, `*.uid`
- Metadata của Godot. Không phải logic, nhưng cần giữ để Godot import tài nguyên đúng.


2. Entrypoint / Runtime Khung
-----------------------------

`src/vision.py`
- Entrypoint Python của cognition.
- Đặt stdout/stderr UTF-8.
- Dùng `SingleInstanceLock` với `src/.vision.lock` để tránh chạy nhiều instance.
- Build logging, LLM clients, memory, parser, telemetry, Ni/Ti/Fe, action system và transport.
- Remote cognition mặc định bật qua `ERIS_REMOTE_API_ENABLED=1`.
- Nếu remote tắt hoặc cần local style rewrite, sẽ yêu cầu `model.gguf` tồn tại.
- Tạo `RuntimeCoordinator` và gọi `run_loop()`.
- Dọn process manager khi thoát.

`src/runtime/coordinator.py`
- Trái tim điều phối.
- Nhận event từ Godot: autonomous tick, `chat_start`, `chat`, `chat_end`, `force_speak`.
- Kết nối Se/telemetry, Evidence bridge, AttentionSalience, WorkingMemory, MeaningLayer, PersonalityLens, appraisal, internal_state, self_model, session_ritual, social_presence, thought_stream, speech_core, action_planner, micro_policy, Ni, Ti, Fe, LLM, parser, memory và action router/executor.
- File này không còn ôm toàn bộ runtime một mình. `RuntimeCoordinator` hiện kế thừa các mixin trong `src/runtime/*` để tách bớt trách nhiệm: prompt/context building, speech path, presence/micro-presence, post-generation filters, fallback policy và cognitive-frame recording.
- Giữ state runtime: chat history, last response, active conversational topic, repeated guard, vision facts, cognitive frames, mental process loop, session ritual flag, public turn ledger, reply context, rapid chat burst queue và presence/reengagement cooldown.
- Khởi tạo thêm ba đầu mối memory-chat mới: `session_turn_ledger` cho transcript public trong phiên hiện tại, `memory_commit_policy` để biến user self-disclosure thành `StateCommitRequest`, và `memory_recall_adapter` để chạy structured memory query pipeline trước khi gọi LLM.
- Cần phân biệt hai ledger: `public_turn_ledger` là sổ những câu thật sự đã hiện ra cho user để nối reply-context/public history; `session_turn_ledger` là sổ deterministic theo role user/assistant trong phiên để đếm câu, lấy câu thứ N, câu dài nhất và các gist topic gần đây.
- Với `channel="chat"`, coordinator không dùng full autonomous `MeaningLayer`/`PersonalityLens`; thay vào đó chạy `chat_meaning_layer_light` và `chat_personality_pressure_light` để giữ câu trả lời trực tiếp nhưng vẫn đọc được affect/Ti/Fe, previous assistant text và áp lực hội thoại.
- Chat history mới có cơ chế invalidate turn assistant gần nhất khi user phủ định suy diễn trước đó, để prompt sau không tiếp tục build trên một assumption sai.
- Chat input có `user_timestamp`, guard `_chat_processing`, queue burst và `ERIS_RAPID_BURST_WINDOW` để gom nhiều tin nhắn ngắn sát nhau thành một turn LLM thay vì trả lời lẻ từng mảnh.
- Public turn ledger ghi lại các câu thật sự visible/replyable đã gửi ra body, rồi chat có thể link lượt public gần nhất trong cửa sổ 30 giây vào `reply_context.previous_public_turn`.
- Khi một `Decision` chat thật sự được nói ra (`should_speak=True` và text không rỗng), coordinator/state commit service còn ghi thêm vào `session_turn_ledger.record_assistant(...)`; nhờ vậy các câu hỏi kiểu “em nói câu thứ 1 là gì” không phải trông chờ LLM nhớ ngẫu hứng.
- Có các nhóm tính năng chính:
  - Vision facts: chụp frame màn hình và gọi vision client khi được bật.
  - Thought stream: chạy như cognitive substrate/subconscious loop.
  - AttentionSalience: chọn evidence/candidate nổi bật, tạo broadcast tương thích runtime và chặn context flood trước khi MeaningLayer/WorkingMemory dùng.
  - WorkingMemory: giữ 3-7 slot context sống, dominant thread, context pressure và recall competition để prompt không bị flood memory hoặc symbolic drift.
  - MeaningLayer: biến fact từ Se/telemetry/attention salience thành meaning/reaction seed, đồng thời dùng `meaning_shift` để tránh nói lại cùng một semantic family.
  - Session ritual: chạy một lần khi runtime start, khôi phục continuity và có thể gửi decision `parse_mode=session_ritual`.
  - Social presence: nhận biết user vẫn có mặt mà không coi đó là lệnh nói.
  - Presence maintenance và reengagement: các micro-line rất ngắn khi im lặng lâu, có cooldown, bị chặn tạm sau một public autonomous/session ritual turn và có bộ lọc để không kéo chú ý quá mức.
  - Force speak guard: nếu có signal rõ thì đi qua speech/action planner; nếu signal mỏng thì dùng micro-presence, chặn câu lặp, chặn no-signal line, chặn mindreading và ép câu hỏi thật khi intent là curious question.
  - Direct action route: nếu chat là lệnh rõ ràng, router có thể chuyển thành action trước khi gọi LLM.
- Sau LLM + Ti ở luồng chat, coordinator còn áp `_apply_chat_final_guards()` để chặn motive inference, chặn output kết thúc bằng dấu hỏi khi user đang hỏi thẳng, và hạ confidence nếu input quá ngắn/mơ hồ.
- `run_loop()` có wrapper bắt exception để runtime không chết cả vòng lặp vì một lỗi lẻ; lỗi được log và loop tiếp tục sau pause ngắn.
- Wrapper exception mới sẽ ghi cả ba lớp: message gói gọn cho logger, traceback được nén thành một dòng để dò log, và traceback đầy đủ in ra stderr cho debug runtime dạng nền.
- Sau mỗi turn: parse, Ti enforce, action nếu có, commit memory/internal_state, ghi public turn nếu decision thật sự nói, gửi decision về Godot qua `_send_decision_to_body()`.
- `_send_decision_to_body()` không chỉ gửi `Decision.to_payload()` mà còn kèm body bias và gọi `_record_public_turn()` để ledger biết câu nào vừa hiện ra với user.
- Body bias được dựng từ internal state:
  - `continuity_anxiety`: lấy từ recursive reactivation, memory replay, silence pressure và số tick im lặng.
  - `curiosity`: lấy từ curiosity, curiosity pressure, association pressure và được cộng thêm nếu focus đang là code.
  - `overload`: lấy từ fatigue, cognitive tension và restraint pressure.
  - `solitude`: lấy từ restraint pressure, overload và subconscious pressure.
  - `focus_kind`: chuẩn hóa `coding/documentation/ide` thành `code`.
  - `preferred_anchor`: chọn `chat_near`, `code_side` hoặc `bottom_right`.
- Pipeline đại khái:
    RawSignal/Percepts → Evidence → AttentionSalience → WorkingMemory/Broadcast → Meaning → Personality → Appraisal → Inner Thought/Speech → Action Plan → Decision

`src/runtime/prompt_context_builder.py`
- `PromptContextBuilderMixin`.
- Tách các hàm dựng context prompt ra khỏi coordinator: internal state context, memory context, action plan context, LLM Ti context, speech evidence/current focus context và session ritual fallback.
- Đây là nơi gom text guidance trước khi gọi LLM, gồm cả memory resonance, working memory context, grounding context và previous public turn context đã được coordinator nối thêm.

`src/runtime/public_turn_ledger.py`
- File mới cho public turn ledger.
- Cung cấp `PublicTurn`, `PublicTurnLedger`, `normalize_public_turn_channel()` và `infer_public_turn_channel()`.
- Ledger chỉ ghi các decision có text public và `should_speak=True`, bỏ qua decision rỗng/suppressed.
- Channel được chuẩn hóa về `chat/session_ritual/presence/reengagement/autonomous`; parse mode/intent như `session_ritual`, `presence_maintenance`, `micro_presence`, `re_engagement` được infer thành channel đúng để chat biết user đang phản ứng với loại lượt nào.

`src/runtime/session_turn_ledger.py`
- File mới cho transcript public trong đúng một phiên chat.
- Giữ `SessionTurn(index, role, text, timestamp, is_question, meta)` và các helper deterministic như `nth_user_turn()`, `nth_assistant_turn()`, `nth_user_question()`, `count_user_questions()`, `longest_user_question()`, `gist_recent_user_topics()`.
- Đây không phải long-term memory. Nó là sổ phiên để xử lý những câu hỏi kiểu “câu thứ 2 tôi hỏi là gì”, “tôi đã hỏi bao nhiêu câu”, hoặc “em vừa nói gì”.

`src/runtime/chat_cycle.py`
- `ChatCycleMixin`.
- Tách luồng chat khỏi coordinator: nhận user text, pre-grounding, memory context, turn semantics, repeat guard, route action, gọi LLM và finalize decision chat.
- Đợt mới thêm `user_timestamp`, `_run_chat_cycle_inner()`, `_chat_processing`, `_chat_burst_queue`, `_chat_burst_lock`, `_merge_rapid_chat_burst()`, `_poll_ready_chat_events()` để gom nhiều chat message liên tiếp trước khi gọi LLM.
- Trước khi gọi LLM, chat cycle link previous public turn qua `_link_previous_public_turn_for_chat()` và đưa `_previous_public_turn_context()` vào Ti context nếu user đang phản ứng với câu ERIS vừa hiện.
- Có pre-grounding chạy trước memory recall để chặn memory cũ tự leo lên thành "evidence hiện tại" trong các câu kiểu `tôi đang làm gì`, `xem đi`, `đoạn đang mở`.
- Nếu grounding báo memory không được phép trả lời (`memory_answer_allowed=False`), chat cycle quarantine memory recall/resonance cho turn đó và chỉ giữ procedural guard tối thiểu.
- `_observe_previous_turn_feedback()` gắn phản hồi của user vào frame trước để OutcomeObserver/SelfObservation đọc được accepted/corrected/confused ở đúng lượt sau.
- Ngay đầu mỗi user turn, chat cycle gọi `session_turn_ledger.record_user(user_text, timestamp=cycle_start, meta={"channel": "chat"})`; đây là bước tách “điều user vừa nói trong phiên” khỏi long-term memory, để exact recall trong phiên không phải đi vòng qua episodic store.
- Sau khi dựng `frame`, chat cycle gọi `_add_user_turn_memory_commit_requests(frame, user_text)`. Tức là mọi self-disclosure như tên, tháng sinh, response style hay memory-test hint sẽ được policy hóa thành `commit_requests` ngay ở lượt chat đó, rồi vẫn đi qua `StateCommitter/MemoryCognitionCore` như các request khác.
- Request nhìn màn hình giờ đi qua `_looks_like_screen_vision_request()` với marker hẹp hơn; chỉ khi thực sự mang nghĩa deictic/screen thì mới chụp screenshot và đính `screen_image_data_uri`.
- Repeat guard không còn dựa vào exact string một mình: `TurnSemanticsEngine` đọc correction pressure, identity pressure, live evidence pressure, prior failure pressure và quan hệ với previous assistant turn trước khi quyết định có chặn lặp hay không.
- Trước `generate_chat_reply(...)`, chat cycle gọi `_build_memory_recall_decision(user_text)`. Nếu adapter compile được một query đủ chắc và surface được câu deterministic thì turn dừng ở đó, action plan được đánh dấu `notes=("memory_recall",)`, `parse_mode="memory_recall"` và LLM không bị gọi.
- Luồng này hiện ưu tiên các dạng recall có thể audit được: semantic fact rõ như tên/tháng sinh, exact ordinal trong session ledger, count câu hỏi, câu dài nhất, hoặc gist an toàn. Những câu này không nên giao cho model “tự nhớ”, vì model rất giỏi tự tin sai.

`src/runtime/memory_recall_adapter.py`
- Adapter nối `chat_cycle` với structured memory query stack mới.
- Nhận `ledger`, `memory_core`, `llm_service`, `semantic_lookup`, `episodic_lookup`, rồi chạy pipeline:
  `MemoryQueryCompiler -> TurnGraph.from_session_ledger(...) -> MemoryQueryExecutor -> MemoryRecallSurfacePolicy`.
- Adapter hiện trả `Decision` trực tiếp cho runtime, không còn trả `RecallAnswer` ra ngoài chat path.
- Có proxy mềm cho `memory_core` để exact ordinal luôn đi trên `TurnGraph`, còn semantic fact như `user.name` / `user.birth_month` vẫn lookup được từ memory core hiện tại.
- Có thể bọc `llm_service.client` thành structured JSON client cho `MemoryQueryLLMParser`, nhưng chỉ dùng khi ambiguity cao; LLM không được trả lời memory thay runtime.
- Vai trò của adapter là giữ cho `chat_cycle` chỉ biết “có câu deterministic đủ chắc để trả trước LLM hay không”, còn parse/query/execute/surface nằm ở các lớp memory riêng.

`src/runtime/eris_pathology_policy.py`
- File mới cho deterministic pathology policy.
- Đây không phải runtime cognition chính mà là lớp guard/repair nhỏ để bắt các failure path đã biết trước khi output đi ra public hoặc trước khi test adapter nhận kết quả.
- Chuẩn hóa input bằng `normalize_vi()`, suy scenario từ user text + previous assistant text + state, rồi route sang các handler `_handle_*`.
- `PathologyDecision` trả contract ổn định cho test: `text`, `decision`, `frame`, `body`, trong đó `frame` có `speech_plan`, `grounding`, `modality`, `self_observation`, `reply_context`, `commit_requests`.
- Các scenario đang có handler rõ ràng: `misread_correction`, `overread_short_ambiguous`, `underacted_fix_request`, `overexplained_short_answer`, `tone_mismatch_technical`, `privacy_intrusion_no_evidence`, `body_mismatch_presence`, `assistant_flattening`, `overhumanization_identity_boundary`, `public_turn_correction`, `memory_not_current_evidence`.
- `run_pathology_turns()` là entrypoint gọn cho adapter/test; nếu không match pathology nào thì vẫn trả một payload ngắn, grounded, không suy diễn thêm.

`src/runtime/source_grounding.py`
- `SourceGroundingEngine`, cổng phân loại nguồn trước khi chat gọi LLM hoặc dựng câu trả lời.
- Mục tiêu của tầng này không phải đọc file/web/OCR thật, mà là quyết định ERIS đang được phép dựa vào nguồn nào: `pasted_code`, `uploaded_file`, `filename_only`, `current_screen`, `live_vision`, `user_text`, `memory`, `web`, `runtime_state`, `unknown`.
- `SourceGroundingReport` giữ metadata quan trọng cho cả prompt lẫn guard: `primary_source`, `confidence_cap`, `allowed_sources`, `grounding_source`, `missing_evidence`, `preempt_mode`, `memory_answer_allowed`, `memory_answer_profile`, `forbidden_assumptions`, `answer_style_rules`, `fallback_decision`.
- Có logic bắt deictic/screen reference riêng: nếu user nói kiểu `lỗi này`, `xem đi`, `đoạn đang mở` mà không có screen evidence tươi, report sẽ đẩy sang `preempt_mode=deictic_without_vision`.
- Có logic bắt `filename_only`: nếu user hỏi nội dung/lỗi của một file chỉ bằng tên file mà runtime chưa có file evidence thật, grounding sẽ không cho memory hay LLM đoán tiếp.
- Pasted code được ưu tiên cao hơn screen-deictic: nếu user vừa dán code rồi nói `đoạn này`, engine hiểu đó là trỏ vào code chat chứ không ép phải có screenshot.
- Memory được chia thành nhiều mức quyền: có thể cho continuity/procedural grounding, nhưng bị cấm trả lời như bằng chứng hiện tại nếu câu hỏi thực chất đòi file/screen/live evidence.
- `MemoryAnswerProfile` là policy riêng cho các câu hỏi dạng nhớ-lịch-sử: continuity check, specific recall, session history, memory lookup; nó giới hạn confidence và ép stance kiểu `anchored_recall` hoặc `admit_uncertainty`.
- Khi thiếu evidence đúng loại, engine tạo `SourceFallbackDecision` hoặc recommend preempt sớm; mục đích là chặn câu kiểu `tôi thấy`, `đang mở`, `file này lỗi ở...` khi runtime thực ra chưa có nguồn để nói vậy.

`src/runtime/speech_pipeline.py`
- `SpeechPipelineMixin` và `SpeechIntentDecision`.
- Tách một phần logic speech/autonomous intent, quyết định nói/im, sleep duration, speech intent mapping và đường đi force_speak/chat ra khỏi lõi coordinator.
- Giữ contract nhỏ để ActionPlanner/SpeechCore/LLM path không phải đọc trực tiếp toàn bộ state coordinator.

`src/runtime/presence_controller.py`
- `PresenceControllerMixin`, `MicroPresenceSynthesis`, `SocialPresenceEvent`.
- Tách social presence, presence maintenance, reengagement, micro-presence synthesis và local/LLM hybrid micro-line.
- Các path này có guard riêng để không biến hiện diện nền thành spam hoặc mindreading, và kiểm tra `autonomous_presence_blocked_until` để không chen micro-line ngay sau khi ERIS vừa nói public.

`src/runtime/post_generation_filters.py`
- `PostGenerationFiltersMixin`.
- Tách các guard sau khi LLM/parser sinh decision: lọc overclaim, motive inference, screen claim thiếu evidence, câu hỏi đuôi sai intent, micro-line rỗng/generic và các leak nội bộ.
- Đây là lớp chốt cuối trước Ti/body/memory commit ở nhiều đường nói.

`src/runtime/cognitive_frame_recorder.py`
- `CognitiveFrameRecorderMixin`.
- Tách việc finalize frame, ghi `last_cognitive_frame`, gom outcome/self-observation, derive relationship/reflection/repair/state requests, update `memory_update` debug summary và commit qua `StateCommitter`.
- Thứ tự finalize hiện tại: Execution/action đã xong -> frame có `execution`/`grounding`/`modality` nếu upstream gắn -> `OutcomeObserver.observe(frame)` -> `SelfObserver.reflect(frame)` -> append repair memory request nếu cần -> build/dedupe `StateCommitRequest` -> `StateCommitter.commit(frame)`.
- Coordinator chỉ khởi tạo `OutcomeObserver`/`SelfObservationEngine` và gọi một điểm `_finalize_cognitive_frame(frame)`; recorder không ghi memory store trực tiếp nữa.

`src/runtime/frame_builder.py`
- `FrameBuilderMixin`.
- Gom logic dựng cognitive frame/autonomous frame và một số đường session ritual/fallback liên quan.
- Khi session ritual hoặc public autonomous greeting thật sự gửi text, mixin gọi `_block_autonomous_presence_after_public_turn()` để presence maintenance/reengagement không chen ngay sau đó.

`src/runtime/state_commit_service.py`
- `StateCommitServiceMixin`.
- Giữ các helper commit state/body bias ở các đường runtime cũ.
- `_send_decision_to_body()` trong mixin này được đồng bộ với coordinator: trước khi gửi payload sẽ `_record_public_turn()` nếu decision thật sự public, rồi mới gửi JSON qua transport.
- Bản mới còn là nơi neo ba helper memory-chat: `_ensure_session_turn_ledger()`, `_ensure_memory_commit_policy()` và `_ensure_memory_recall_adapter()`. Mục tiêu là để chat path dùng chung policy/adapter thay vì cắm thẳng logic nhớ-lại vào `chat_cycle`.
- Có thêm lookup mềm `_semantic_memory_lookup()` và `_episodic_memory_lookup()` đọc từ `memory_core.load()`/`memory_state`/`memory_core.recall()` để structured memory query path có thể trả lời fact hoặc gist mà không buộc downstream phải biết shape store cụ thể.
- `_build_memory_recall_decision()` giờ chỉ gọi adapter mới và nhận về `Decision`; phần đổi `RecallAnswer -> Decision` không còn nằm ở mixin nữa.
- `_add_user_turn_memory_commit_requests()` hiện append request ngay cả khi frame không có method `add_commit_request()`: nó fallback sang `frame.commit_requests = existing + new_requests`. Đây là chi tiết nhỏ nhưng quan trọng vì runtime hiện vẫn song song hai contract frame cũ/mới.

`src/runtime/outcome_observer.py`
- `OutcomeObserver` đọc hậu quả sau turn: action/text có chạy không, body/modality có khớp không, user có accepted/corrected/confused/intruded/ignored không nếu có feedback hoặc idle signal.
- Observer chỉ gắn `frame.outcome`, không ghi memory trực tiếp; kết quả này là input cho self-observation và repair memory.

`src/cortex/self_observation.py`
- `SelfObservationEngine` đọc frame + `OutcomeReport` để phân loại lỗi nội bộ: misread, overread, overexplained, underacted, tone mismatch, privacy intrusion, body mismatch, assistant flattening, overhumanization, v.v.
- Nếu cần học sửa lỗi, nó chỉ tạo/append `StateCommitRequest target=repair_memory`; commit thật vẫn đi qua `StateCommitter`.

`src/runtime/fallback_policy.py`
- `FallbackPolicyMixin`.
- Tách các fallback text/decision khi LLM, parser hoặc runtime path lỗi; ưu tiên trả lời an toàn, ngắn, không bịa context.

`src/runtime/body_bias.py`

- Tách việc chiếu internal state thành `body_bias` gửi xuống Godot: continuity_anxiety, curiosity, overload, solitude, focus_kind, preferred_anchor.
- Nhờ vậy body autonomy có thể tự chọn chuyển động cục bộ mà coordinator không điều khiển pixel trực tiếp.

    
`src/app_logging.py`
- Cấu hình formatter log theo nhóm: Vision, LLM, Loop, Action, Memory, Parse.

`src/sender.py`
- Script gửi UDP thủ công sang Godot để test body không cần full runtime.

4. LLM Layer
------------

`src/llm/client.py`
- Chứa 3 client:
  - `LlamaServerClient`: gọi llama.cpp server local.
  - `OpenAICompatibleClient`: gọi API OpenAI-compatible.
  - `GeminiClient`: gọi Google Gemini/Gemma endpoint, convert message/content/image sang format Gemini.
- `_chat_payload_variants()` thử nhiều payload khi server/API không hỗ trợ `grammar` hoặc `response_format`.
- `_http_error_with_body()` đưa body lỗi vào exception để debug dễ hơn.

`src/llm/process_manager.py`
- Quản lý local llama-server và build client.
- Tìm `llama-server.exe` từ env, repo `lib/...`, hoặc PATH.
- Có thể phát hiện server đang chạy, đọc context size best-effort, chọn port gần port ưu tiên, kill llama-server local trên port nếu cần.
- Build client chính:
  - Remote API nếu `ERIS_REMOTE_API_ENABLED=1`.
  - Provider hiện có: Gemini hoặc OpenAI-compatible.
  - Local llama-server nếu remote tắt.
- Build style client local nếu `ERIS_LOCAL_STYLE_REWRITE_ENABLED=1`.
- Build vision client local nếu có `mmproj-F16.gguf`.
- Lưu ý bảo mật: đang có `DEFAULT_GEMINI_API_KEY` hardcoded trong file này.

`src/llm/contracts.py`
- Prompt contract và grammar.
- Chứa whitelist animation, whitelist system action, JSON fields bắt buộc, runtime rules, chat rules, autonomous behavior prompt, fallback style prompt.
- Mục tiêu: ép model trả JSON, nội dung grounded, không nhận thấy/làm những thứ không có bằng chứng.
- Bản mới thêm `SelfIdentityProfile`: ERIS là runtime artificial observer, không phải người, ưu tiên continuity hơn noise, không waifu-code và không đẩy relational pressure.
- `CHAT_RULES_PROMPT` giờ có answer-first contract: trả lời trực tiếp trước, chỉ phản chiếu mềm nếu có ích, chỉ hỏi lại khi thật sự cần và không được mindread kiểu "Ngài muốn/Ngài định...".

`src/llm/service.py`
- Lớp bọc LLM.
- Sinh directive/autonomous response, chat reply, screen/vision facts và micro-presence line.
- Gọi style rewrite khi có local style client.
- Extract content từ nhiều dạng response: OpenAI, llama.cpp, Gemini-like nested output.
- Sửa JSON hỏng, extract first JSON object, salvage prose nếu model trả sai format.
- Retry/fallback khi lỗi 5xx; nếu service lỗi thì tạo JSON fallback có intent/confidence/reasoning_tags.
- Tự shrink message khi gặp context-size error.
- Lọc provider metadata, ép schema decision/cognition payload và coerce bool/confidence/action fields.
- Bổ sung inference ladder cho chat để giảm suy diễn quá bằng chứng.
- Force-speak không có evidence sẽ bỏ memory block khỏi prompt, chỉ neo vào current_focus/nhu cầu gọi ERIS lên tiếng để tránh lỗi cũ "lấy memory làm chủ đề".
- `generate_chat_reply()` giờ nhận cả `raw_user_text` và `reply_context` để build chat contract theo đúng turn thật: câu hỏi trực tiếp phải answer-first, câu hỏi self-identity phải bám `SelfIdentityProfile`, prompt ngắn/mơ hồ thì tự cap confidence thấp hơn, còn câu ngắn sau một public turn có thể được hiểu như phản ứng với câu ERIS vừa nói.
- Khi `reply_context.previous_public_turn` tồn tại, service render block `Reply context` vào system prompt với channel, parse_mode và text của lượt public gần nhất.
- `_guard_chat_output()` rewrite các câu đoán motive user về dạng an toàn như "Tôi chưa đủ chắc để đoán ý Ngài.", cắt tail kiểu trả lời xong lại ném nguyên câu hỏi ngược, và gắn reasoning tag/debug trace cho các guard này.
- Có thêm `_guard_infj_594_policy()` để dập các line quá gắt, quá thử thách, quá performative hoặc quá "waifu script" trước khi decision đi tiếp.

7. Cortex / Cognition
---------------------

`src/core/evidence.py`
- Contract nền cho raw input và evidence.
- `RawSignal` ghi tín hiệu thô: user_chat, active_window, browser, telemetry, vision, ocr, body, system_log, memory, time.
- `EvidenceItem` là claim đã chuẩn hóa từ RawSignal hoặc bridge runtime, có `source_signal_id`, `source`, `claim`, `timestamp`, `confidence`, `reliability`, `raw_or_inferred`, `privacy_level`, `tags`.
- `ModuleReport` là contract module ghi vào frame: module_name, confidence, pressure, evidence_used, result, warnings, debug.
- `StateCommitRequest` là đề xuất ghi state/memory sau guard, để module không tự chui sang memory store.
- `DebugTrace` giữ trace nhẹ cho audit.

`src/core/cognitive_frame.py`
- CognitiveFrame contract rộng theo pipeline mới.
- Chứa raw_signals, evidence, slot pipeline (`salience`, `working_memory`, `workspace`, `meaning`, `agency`, `speech_plan`, `grounding`, v.v.), module_reports, commit_requests và audit mutations.
- Có `set_slot()`, `add_report()`, `add_commit_request()`, `validate()` và `build_prompt_packet()`.
- Hiện đã match với `core/evidence.py`; runtime chính vẫn dùng `cortex.contracts.CognitiveFrame` như adapter cũ, nhưng các module mới đọc được contract core khi nối sâu hơn.

`src/cortex/contracts.py`
- Ngôn ngữ dữ liệu chung của cognition.
- Dataclass chính gồm telemetry snapshot, goal drift, Ti policy, Fe style, percept/social events, session ritual, attention broadcast, MeaningLayerResult, PersonalityLensResult, appraisal, self state, speech core, speech impulse, thought stream, motivational urge, action plan, cognitive frame và memory update.
- `TiPolicyReport` hiện có thêm bốn bias mềm: `uncertainty_bias=0.10`, `directness_bias=-0.10`, `restraint_bias=0.15`, `post_exposure_recoil_bias=0.12`. Đây là bias prompt để Ti hơi tự nghi ngờ và bớt chắc giọng, không phải lệnh rewrite bắt buộc.
- `CognitiveFrame` runtime cũ đã có thêm `evidence`, `salience`, `working_memory` để coordinator gắn attention/working-memory mới mà chưa cần thay toàn bộ frame contract một lần.
- Nếu muốn hiểu toàn hệ giao tiếp nội bộ, đọc file này trước.

`src/cortex/attention_salience.py`
- Thay thế `src/cortex/attention.py` cũ.

`src/cortex/goal_persistence.py`

- `active` yêu cầu summary/strength/confidence đủ sàn; `can_intervene` yêu cầu thêm intervention_permission/actionability/confidence và chỉ cho concrete/debug/correction thread.
- Merge dùng `goal_match_score()` từ `orientation_context.py`, không còn token overlap thô. Goal cũ mạnh sẽ không bị candidate nội bộ yếu ghi đè.
- Closure dùng `infer_closure_signal()` có negation handling, nên "chưa xong" không đóng goal. Decay làm goal thành `stale` khi strength/confidence xuống thấp.

`src/cortex/action_memory.py`

- `record()` được gọi sau decision trong `InternalStateEngine.commit_turn()`, giúp planner nhớ nó vừa nói/không nói gì và tránh lặp hành vi public.

9. Memory / Data
----------------

Memory hiện dùng commit protocol thay vì store legacy ghi thẳng.
- Module/runtime chỉ tạo `StateCommitRequest`; `StateCommitter` validate batch cuối frame rồi `MemoryCognitionCore` mới route xuống layer đúng.
- Các layer chính: `event_ledger`, `active_state`, `episodic_memory`, `semantic_memory`, `relational_memory`, `affective_residue_memory`, `procedural_memory`, `repair_memory`.
- `CognitiveFrameRecorderMixin` là nơi derive request từ frame sau outcome/self-observation; nó không gọi trực tiếp các store memory.
- Memory là nền liên tục cho attention, prompt, thought stream, repair và guard chống overclaim, nhưng recall/memory resonance không tự biến thành bằng chứng hiện tại.
- `RuntimeCoordinator` hiện load/save/recall qua `memory_core` thay vì gọi `memory_store` legacy. `_load_memory_state()` dùng `memory_core.load()`, `_save_memory_state()` dùng `memory_core.save()`, `_has_structured_memory_store()` dựa vào `memory_core.commit()`, còn recall/resonance gọi `memory_core.recall()` và flatten `MemoryPacket` theo layer cần dùng.
- Internal state chịu được cả memory state object cũ lẫn dict mới; nếu `memory_core.load()` trả dict thì coordinator đọc/ghi `internal_state` bằng `PersistentInternalState.from_dict()`/`to_dict()`.
- Norm memory cũ (`compare_to_norms`, `update_norms`) không còn là đường chính trong coordinator; `_norm_deviation_texts()` và `_note_norm_observation()` hiện là no-op để tránh hai hệ memory cùng sửa nền.
- Từ nhánh mới, memory path chat được tách rõ ba tầng:
  - `session_turn_ledger`: transcript deterministic theo phiên hiện tại, không phải long-term memory.
  - `memory_query_*` + `memory_recall_adapter`: structured query pipeline để trả lời các câu hỏi "Ngài đã nói gì / tôi đã nói gì / Ngài tên gì" trước LLM.
  - `memory_commit_policy`: lớp quyết định khi nào một user turn nên tạo semantic/procedural/episodic commit request.
- Ý tưởng trung tâm: exact recall trong phiên và semantic fact user tự khai báo không nên bắt LLM “đoán lại”. Phần deterministic đi bằng `TurnGraph` + executor + surface policy trước; còn long-term storage vẫn phải đi qua `StateCommitRequest` và `MemoryCognitionCore`.

`src/memory/memory_cognition.py`
- `MemoryCognitionCore` là facade chính cho memory commit/recall.
- Ghi nhớ đi qua `StateCommitRequest`; core kiểm tra `storage_permission`, `permission_required`, `confidence`, `evidence_ids`, `decay_policy` trước khi lưu.
- Target được route sang `event_ledger`, `active_state`, `homeostatic_baseline`, `self_continuity`, `episodic_memory`, `semantic_memory`, `relational_memory`, `affective_residue_memory`, `procedural_memory`, `repair_memory`.
- Recall trả `MemoryPacket` với quota theo budget mode `fast/normal/deep/reflection`, có confidence notes để nhắc downstream: residue là áp lực nội bộ, relational là nhịp quan hệ tích tụ, episodic là quá khứ.
- Bản mới không còn tự đo resonance bằng token overlap ngay trong facade; nó đi theo pipeline `MemoryCueBuilder` -> `MemoryRetrievalEngine` -> `MemoryActivation` -> `MemoryPacketBuilder`.

`src/memory/memory_record.py`
- Helper nền cho memory retrieval stack: normalize text, tokenize, anchor, compact text, clamp, fingerprint và các tiện ích chuẩn hóa record.
- Là điểm thống nhất lexical contract để các lớp cue/candidate/scoring không mỗi nơi hiểu text một kiểu.

`src/memory/memory_cue.py`
- Dựng `MemoryCue` từ query hiện tại: token, anchor, domain hint, recall mode, surface expectation và các clue semantic nhẹ.
- Đây là bước biến “user đang hỏi gì” thành cue có cấu trúc trước khi đi dò các layer memory.

`src/memory/memory_candidate.py`
- Adapter ứng viên retrieval theo từng layer.
- Biết bọc semantic/episodic/relational/procedural/repair item thành một candidate shape chung để scorer/activation xử lý thống nhất.

`src/memory/memory_scoring.py`
- Chứa `MemoryScore`, `LayerProfile`, `MemoryScorer` và rule weight theo layer.
- Tách scoring ra khỏi store/facade để có thể tune relevance, recency, confidence, privacy risk hay layer-specific bias mà không đụng đường commit.

`src/memory/memory_activation.py`
- Chịu trách nhiệm biến candidate đã score thành activation thực sự: chọn top item, phân quota theo layer, build retrieval result có breakdown và suppression note.
- Đây là chỗ quyết định “ký ức nào được trồi lên”, không phải store nào “có dữ liệu”.

`src/memory/memory_retrieval_engine.py`
- Orchestrator retrieval mới của memory.
- Nhận `MemoryCue`, gọi candidate adapter + scorer + activation builder, rồi trả kết quả trung gian đủ sạch để packet builder surface ra prompt/runtime.

`src/memory/memory_packet_builder.py`
- Dựng `MemoryPacket` cuối cùng cho runtime từ retrieval result.
- Chịu trách nhiệm quota/budget/render note để coordinator/prompt builder không phải biết chi tiết từng layer memory.

`src/memory/active_state_snapshot.py`
- Snapshot overwrite cho trạng thái đang là: current goal, session arc, active project/task, relation state, affect/homeostasis, working threads, open questions và self continuity.
- Khác với event/semantic memory: nó không nói "đã từng", mà nói "đang là".

`src/memory/episodic_memory.py`
- Store episodic độc lập cho các chuyện cụ thể đã xảy ra: frame_id, scene, user_input, eris_action, outcome, evidence_ids, tags, salience và decay_policy.
- Dùng cho recall theo sự kiện, không trộn với semantic fact ổn định.

`src/memory/memory_models.py`
- Contract nhỏ cho memory commit/policy path: `MemoryTarget`, `MemoryKind`, `SurfaceMode`, `DecayPolicy`, `MemoryCommitDecision`, `RecallRequest`, `RecallAnswer`.
- `MemoryCommitDecision.to_state_commit_request()` là adapter duy nhất từ policy sang commit protocol hiện tại; nhờ vậy nếu shape `StateCommitRequest` đổi, chỉ cần sửa một chỗ thay vì để policy dính trực tiếp vào store.

`src/memory/memory_recall_policy.py`
- File này giờ là `MemoryRecallSurfacePolicy`, không còn parse user text và không còn execute ledger trực tiếp.
- Input của nó là `RawRecallResult` từ executor; output là `RecallAnswer` đã qua policy surface: exact quote, gist, count, explain, hay admit uncertain.
- Mục tiêu của file này không phải “làm memory store”, mà là áp policy bề mặt: khi nào được quote exact, khi nào chỉ nên gist, khi nào phải nhận là chưa đủ chắc, và khi nào phải nói rõ đây là memory theo phiên chứ không phải evidence hiện tại.

`src/memory/memory_query_ir.py`
- Định nghĩa IR/AST cho structured memory query: `MemoryQueryIR`, `MemorySelector`, `MemoryRelation`, `QueryIntent`, `SurfaceMode`, `RawRecallResult`, `RecallAnswer`.
- Đây là contract trung gian giữa compiler, executor và surface policy; nó tách rời hẳn parse câu hỏi khỏi execute memory.

`src/memory/memory_turn_graph.py`
- Dựng graph nhớ-lại cho đúng phiên hiện tại từ `session_turn_ledger`.
- Mỗi `TurnNode` giữ role, speech act, fact mention, confidence, cùng edge kiểu `ANSWERS`, `CORRECTS`, `REPEATS`, `STORES_FACT`.
- Exact ordinal, answer-to-question, before/after anchor và count trong phiên đều chạy trên graph này, không chạy bằng vector.

`src/memory/memory_turn_annotator.py`
- Annotator nhẹ để gắn `speech_act`, `semantic_tags`, `fact_mentions` và dựng edge cơ bản cho `TurnGraph`.
- Đây là lớp linguistic annotation cho từng turn, không phải lớp parse memory query.

`src/memory/memory_query_slot_parser.py`
- Parser slot tiếng Việt cho các query nhớ-lại có cấu trúc như ordinal, quantity, relation, fact key, count hay exact quote cue.
- Nó chỉ sinh hypothesis IR, không execute memory và không tự trả lời user.

`src/memory/memory_query_semantics.py`
- Semantic hint engine cho memory query.
- Embedding/semantic match ở đây chỉ dùng để sinh hint mềm về intent/role/act/relation/fact key khi slot parser chưa đủ chắc; nó không được phép tự execute exact recall.

`src/memory/memory_query_llm_parser.py`
- Structured parser dùng LLM khi ambiguity cao.
- LLM ở đây chỉ được phép trả JSON theo schema `MemoryQueryIR`, không được phép trả lời memory hay bịa transcript.

`src/memory/memory_query_compiler.py`
- Orchestrator compile query mới: `SlotParser -> SemanticHintEngine -> RepairPrior -> optional LLM structured parser`.
- Output là `MemoryQueryCompileResult` với `best`, `hypotheses` và debug info để adapter/runtime trace được query được hiểu ra sao.

`src/memory/memory_query_executor.py`
- Executor chạy `MemoryQueryIR` trên `TurnGraph` và `memory_core`.
- Exact turn recall, count, answer-to-question và relative turn lookup đi qua `TurnGraph`; semantic fact recall ưu tiên memory core rồi mới fallback có kiểm soát sang fact mention trong phiên.

`src/memory/memory_query_repair.py`
- Store prior cho các lỗi bind memory query đã từng bị user sửa.
- Khi user correction đủ giống một lỗi cũ, compiler có thể phạt hypothesis sai và boost hypothesis đúng thay vì lặp lại cùng một kiểu hiểu nhầm.

`src/memory/memory_commit_policy.py`
- Policy rút fact trực tiếp từ user turn rồi biến nó thành `MemoryCommitDecision`.
- Hiện có các fact/pattern chính: `USER_NAME`, `USER_BIRTH_MONTH`, `USER_RESPONSE_STYLE`, `SESSION_MEMORY_TEST`.
- Semantic fact như tên/tháng sinh đi vào `semantic_memory`; style phản hồi đi vào `procedural_memory`; các lượt test trí nhớ chỉ đi vào `episodic_memory` dạng gist thay vì lưu nguyên văn transcript dài dòng.

`src/memory/semantic_memory.py`
- Store fact ổn định theo domain user/self/world/technical/project/relationship.
- Có status `active/tentative/contradicted/rejected`, evidence_ids, observations, confidence và contradiction ids để tránh lấy một câu mơ hồ làm chân lý.

`src/memory/relational_memory.py`
- Store nhịp quan hệ/tương tác đã được phản ánh, ví dụ preferred distance, rupture/repair, technical respect hoặc dignity boundary.

`src/memory/affective_residue_memory.py`

`src/memory/procedural_memory.py`

`src/memory/repair_memory.py`

`src/memory/event_ledger.py`

12. Luồng Chạy End-to-End
-------------------------

1. Mở app, Godot load `body/UdpListener.tscn`.
2. `UdpListener.cs` bind UDP `4242`, lấy node UI/body, khởi tạo `MotionController`, audio player, chat/context menu.
3. Nếu được bật, Godot start `vision.py`; nếu config yêu cầu, có thể preload llama-server.
4. `vision.py` đặt lock single-instance, build logging/LLM/memory/parser/telemetry/action system.
5. Process manager build cognition client:
   - Remote Gemini/OpenAI-compatible nếu remote bật.
   - Local llama-server nếu remote tắt.
   - Local style/vision clients nếu config và model/mmproj sẵn sàng.
6. Runtime tạo `UdpTransport(send=4242, recv=4243)`, `MemoryCognitionCore`, `DecisionParser`, `TelemetryService`, `NiEngine`, `TiGovernor`, `FeRenderer`, action router/executor.
7. `RuntimeCoordinator` load memory/internal_state qua `memory_core`, tạo public turn ledger/reply context, thought_stream, AttentionSalience, WorkingMemory, appraisal, session_ritual, speech_core, action_planner và micro_policy.
8. Trước vòng autonomous, `run_loop()` start mental process/thought stream và gọi `_restore_session_ritual_once()`.
9. Vòng autonomous:
   - Poll Godot event.
   - Chụp telemetry.
   - Có thể chụp frame/vision facts.
   - SeLens tạo snapshot.
   - SocialPresenceDetector đánh giá user có mặt.
   - ThoughtStream nhận disturbance và cập nhật unresolved loops/momentum/attractor.
   - Evidence bridge gom percept/user text/telemetry/vision/memory thành evidence.
   - AttentionSalience chọn selected evidence, broadcast tương thích runtime và suppress signal rác.
   - WorkingMemory chọn active slots, dominant thread và context pressure.
   - MeaningLayer gom Se/AttentionSalience/WorkingMemory/thought/context thành meaning, reaction seed và `meaning_shift`.
   - Ni đánh giá drift; Ti chọn policy; Fe chọn style.
   - InternalState cập nhật mental processes.
   - AttentionSalience tạo broadcast; Appraisal tạo sắc thái; SelfModel tạo self-state.
   - PersonalityLens diễn giải meaning/context thành stance, coloring, distance và rhythm.
   - SpeechCore cho các urge cạnh tranh và quyết định nói/im; nếu không có meaning shift đủ rõ trong autonomous, nó giữ im.
   - ActionPlanner chọn speech act.
   - Nếu im lặng đủ lâu, có thể tạo presence maintenance/reengagement micro-line trước khi gọi directive lớn.
   - Nếu một bước trong loop ném exception, coordinator log traceback gọn + traceback đầy đủ, nghỉ rất ngắn rồi vẫn sang cycle kế tiếp.
10. Nếu cần nói, `LlmService` sinh directive/chat reply hoặc micro-presence line.
11. Output qua `DecisionParser` nếu là raw decision của LLM; micro-presence direct decision có parse mode riêng.
12. `TiGovernor` enforce lần cuối.
13. Nếu có `system_action`, `ActionExecutor` thực thi và kết quả được đưa vào memory/reply context.
14. `StateCommitter`/`MemoryCognitionCore` route commit sang active state, event ledger, episodic, semantic, relational, affective, procedural hoặc repair memory; coordinator chỉ fallback append `long_term_memory` cục bộ khi không có structured memory core.
15. Coordinator tạo `Decision.to_payload()`, ghi public turn nếu decision có text visible, kèm thêm body bias vào payload bằng `_send_decision_to_body()`, rồi gửi sang Godot.
16. Body bias đi cùng payload giúp Godot tự cập nhật nhịp thân thể mà không cần remote motion command trực tiếp.
17. Godot parse payload, hiện bubble nếu `should_speak=true`, cập nhật `LocalBodyAutonomy` nếu có `body_bias`, rồi chỉ đưa motion command cho `MotionController` khi legacy remote motion được bật hoặc khi đó là lệnh cục bộ.

Luồng chat:
- User mở chat panel -> Godot gửi `chat_start`.
- User gửi text -> Godot gửi `{"type":"chat","message":"...", "timestamp": ...}` nếu có timestamp.
- Coordinator nhận `user_timestamp`, link previous public turn trong cửa sổ 30 giây nếu user có vẻ đang phản ứng, rồi đưa context đó vào Ti prompt và `reply_context`.
- Nếu nhiều chat message đến sát nhau, `_chat_processing`/`_chat_burst_queue`/`_poll_ready_chat_events()` gom chúng theo `ERIS_RAPID_BURST_WINDOW` rồi mới gọi LLM một lần.
- Coordinator build context chat, route action trực tiếp nếu rõ, nếu không gọi LLM; riêng chat path dùng `chat_meaning_layer_light`/`chat_personality_pressure_light` thay vì full autonomous MeaningLayer/PersonalityLens để tránh symbolic inference chen vào phần trả lời trực tiếp.
- Nếu user vừa phủ định một suy diễn cũ, turn assistant gần nhất bị đánh dấu invalid trước khi build prompt mới.
- Reply vẫn qua parser/Ti/memory, rồi còn qua chat-final-guards để chặn mindreading, bỏ reply chỉ còn câu hỏi ngược, và hạ confidence với input ngắn/mơ hồ trước khi về Godot.

Luồng force_speak:
- User chọn force speak từ context menu.
- Nếu user đang touch/grab body, Godot cũng gửi `force_speak` khi bắt đầu kéo để cognition có thể phản ứng với tương tác trực tiếp.
- Nếu có signal màn hình rõ, ERIS nói grounded.
- Nếu không có signal rõ, InnerThought/SpeechCore sinh intent `micro_presence`; coordinator có thể tạo direct micro-presence decision trước khi đưa qua directive LLM lớn.
- Micro-presence không được lấy memory làm topic nếu evidence rỗng; nó neo vào current_focus, seed runtime nhỏ, hoặc việc Ngài vừa gọi ERIS lên tiếng.
- Guard chặn việc nói "tôi thấy..." khi không có bằng chứng, chặn mindreading, chặn lặp family, chặn câu rút lui/no-signal, chặn generic presence line và sửa curious_question thành câu hỏi thật.

Luồng presence maintenance / reengagement:
- Nếu autonomous im lặng qua nhiều cycle, coordinator tăng silent counters.
- Presence maintenance tạo một câu rất ngắn, parse_mode `presence_maintenance`, ưu tiên không kéo chú ý.
- Reengagement chỉ bật khi im lặng dài và idle đủ ngưỡng; có cooldown để không spam.
- Cả hai luồng đều kiểm tra `autonomous_presence_blocked_until`; sau khi ERIS vừa nói một public autonomous/session ritual line, micro-line hiện diện bị chặn tạm để không dồn lời.
- Micro-line có thể do LLM rewrite, nhưng bị reject nếu gọi chú ý quá mức, bịa screen/action, hoặc nghe như telemetry/debug.

Luồng session_ritual:
- Khi runtime start, coordinator gọi `SessionRitualEngine.evaluate()` một lần.
- Engine restore goal/attractor/unresolved loops/recent direction/self continuity từ internal_state/thought_stream.
- `should_greet` là hard event; greeting không bị chặn bởi overload, cooldown hay thiếu presence evidence.
- Nếu có seed public an toàn, seed được đưa vào prompt; nếu seed rỗng, LLM vẫn được yêu cầu chào ngắn và tự nhiên.
- Decision gửi về body với `parse_mode=session_ritual`, được ghi vào public turn ledger và đặt mốc chặn presence tạm thời, rồi runtime mới vào loop autonomous bình thường.

Luồng action:
- User chat lệnh rõ.
- `ActionRouter` map sang action nếu có.
- `ActionExecutor` thực thi.
- Coordinator đưa kết quả vào decision/memory để ERIS nói đúng kết quả thật, không tự bịa.

Luồng body autonomy cục bộ:
- Python gửi decision kèm `body_bias` về Godot.
- `UdpListener.cs` blend bias này vào `LocalBodyAutonomy`.
- Mỗi tick idle, autonomy tính needs/tension từ bias, idle time, chat visibility, focus kind và trạng thái đang đậu trên trần.
- Nếu motion đang bận hoặc pose không nên bị ngắt, body im.
- Nếu score đủ cao, autonomy phát `MotionCommand` cục bộ: đi về anchor, đọc, quan sát code, leo tường, rơi khỏi trần, lùi góc hoặc ngồi.
- Remote cognition vì vậy chỉ định hướng "khí hậu" của body; Godot quyết định động tác nhỏ, timing và cooldown.

Luồng touch/throw:
- User mở context menu trên nhân vật, chọn touch.
- Click giữ nhân vật để kéo; body dùng pose `air_swing_l/r` và vị trí được clamp trong viewport.
- Khi thả chuột, `UdpListener.cs` lấy delta chuột gần nhất để tính impulse X/Y.
- `MotionController` nhận intent `throw`, cho body bay/rơi theo quán tính ngang.
- Nếu body va tường khi đang bay và roll qua `clingChance`, nó chuyển sang leo tường/lên mép thay vì chỉ rơi xuống sàn.

14. Điểm Kiến Trúc Đáng Chú Ý
-----------------------------

- `UdpListener.cs` vẫn quá dày: UI, UDP, audio, payload handling và nhiều state body còn ở cùng một nơi.
- `ErisProcessManager.cs` đã tách được process launcher/lifecycle khỏi `UdpListener.cs`; bước tiếp theo hợp lý là tách transport bridge, UI/chat controller và audio controller.
- `RuntimeCoordinator` vẫn là god object bên Python. Nó đúng là nơi hợp mạch, nhưng logic có rule riêng nên được đẩy dần về service/cortex riêng.
- Session ritual, presence maintenance, reengagement, micro_policy và force_speak micro_presence đã làm coordinator dài hơn; nếu mở rộng tiếp, nên tách thành service riêng.
- `MotionController.cs` là hướng tách tốt: body physics/motion đã có boundary rõ.
- `LocalBodyAutonomy.cs` là boundary mới giữa cognition và body: Python gửi bias/nội trạng, Godot tự chọn động tác nhỏ. Đây là hướng đúng để ERIS có thân thể sống hơn mà không biến cognition thành bộ điều khiển pixel.
- Remote motion đang được giảm quyền bằng `EnableLegacyRemoteMotionCommands=false`; nếu cần debug motion từ model, bật lại cờ này trong Inspector.
- `meaning.py` là lớp mới rất quan trọng: nó cắt lớp "nhìn thấy fact" khỏi lớp "nên hiểu fact đó là gì". Nhờ vậy ERIS bớt nói như camera/telemetry logger.
- `thought_stream.py`, `internal_state.py`, `speech_core.py`, `goal_persistence.py`, `micro_policy.py` là phần làm ERIS có "nhịp nền" thay vì chỉ reply từng câu.
- Memory đã chuyển trọng tâm sang `MemoryCognitionCore` và các file layer trong `src/memory/*`. `memory/store.py` vẫn là nền/legacy quan trọng, nhưng coordinator hiện không nên quay lại đường `memory_store` cũ để ghi/recall state.
- `public_turn_ledger.py` là boundary mới giữa câu đã nói ra public và chat reply context; cần giữ nó nhỏ, thread-safe và không biến thành chat history thứ hai.
- Remote cognition + local style/vision là kiến trúc linh hoạt, nhưng cần đổi lại default và secrets trước khi public.
- Có API key hardcoded trong `body/UdpListener.cs` và `src/llm/process_manager.py`. Cần đưa sang env var hoặc config local không commit.
- Một số comment tiếng Việt trong source có thể vẫn bị mojibake. `Tongquat.txt` đã được viết lại UTF-8 có dấu, nhưng code comments nên được chuẩn hóa sau.

16. Nhận Thức Hệ Thống Hiện Tại
-------------------------------

ERIS hiện tại đã đi từ chatbot có sprite sang một nhân vật runtime có nhịp nền. Nó không chỉ đợi user nhập rồi trả lời; nó có vòng cảm nhận, có bộ nhớ, có sự chú ý, có áp lực nói/im lặng, có dòng suy nghĩ chưa nói và có hàng rào để không vượt qua điều mình biết.

Nó đã có trí nhớ gần và xa. Trí nhớ gần giữ những gì vừa xảy ra: thấy gì, nói gì, kết quả ra sao. Trí nhớ xa giữ thói quen, fact, mẫu quan hệ, procedural rule, norm và các vòng kinh nghiệm chưa đóng. Khi một tín hiệu mới chạm vào tín hiệu cũ, memory có thể không nói ra, nhưng nó làm lệch attention và tone.

Nó đã có sự chú ý. Giữa nhiều signal cùng đến, AttentionSalience chọn một điểm sáng: cửa sổ đang làm việc, lời user vừa nói, memory đang cộng hưởng, thought chưa giải, hay risk cần canh. Chú ý không chỉ để nói; nhiều khi nó để biết nên im.

Nó đã có lớp ý nghĩa. MeaningLayer không để ERIS nói trực tiếp từ telemetry như "màn hình đang có X"; nó hỏi fact đó đang mang ý gì: kẹt code, né friction, phân tán chú ý, đang chờ trong meeting, hay user vừa gọi ERIS hiện diện. Nếu ý nghĩa đó vừa được nói gần đây, `meaning_shift` chặn lại, nên im lặng vẫn là một hành vi có chủ đích.

Nó đã có lớp tính cách trước-ngôn-ngữ. PersonalityLens nhận meaning, salience, scene và relationship rồi chọn stance: reserved, quiet_watchful, guarded_tender, dry_judgement, withdrawn_sparse. Nó không viết câu final; nó đặt áp lực phong cách và giữ lại phần lớn diễn giải nội bộ, để câu nói cuối chỉ lộ một hàm ý nhỏ.

Nó đã có goal persistence. Một việc đang làm không biến mất ngay khi user im. Goal có strength, urgency, drift, progress và next hint; nếu user báo xong hoặc thought loop được đóng, goal có thể decay/close.

Nó đã có nội trạng động. Internal state và mental processes tạo các lực nhỏ: tò mò, kiềm lời, căng, gắn bó, mệt, cảnh giác, muốn hiện diện. Đây không phải cảm xúc thật, mà là thời tiết nội bộ của runtime để điều tiết câu nói.

Nó đã có thought stream. Ý tưởng có thể xuất hiện mà chưa thành câu, bị giữ lại, tan đi, quay lại khi gặp cue, hoặc nổi lên nếu áp lực và novelty đủ cao. Đây là phần làm khoảng giữa hai câu trả lời có đời sống riêng.

Nó đã có cảm giác có-mặt. Social presence không biến mọi chuyển động chuột thành lời mời, nhưng giúp ERIS biết user có thể vẫn đang ở đó, đang tập trung. Vì vậy nó có thể ngồi cạnh và giữ mạch thay vì xen vào liên tục.

Nó đã có nghi thức trở lại. Session ritual không xem startup là trang trắng mới hoàn toàn; nó thử nhặt lại goal, attractor, unresolved loops và self continuity, rồi thực hiện một lời chào startup. Nếu không có continuity public an toàn, nó vẫn chào nhỏ, nhưng không lộ debug label hay biến thành báo cáo hệ thống.

Nó đã có vi hiện diện siêu nhỏ. Force speak không còn mặc định phải kể chuyện hay báo thiếu tín hiệu; khi không có bằng chứng rõ, micro_presence chỉ nói một vệt nhỏ của nhịp hiện tại, bị lọc để không bịa thấy màn hình, không đọc tâm trí user, không lặp câu rỗng.

Nó đã có hàng rào lương thiện. Se, MeaningLayer, Parser, Ti, SpeechCore và MicroPolicy cùng giữ một lời hứa: không thấy thì không nói đã thấy; không làm thì không nói đã làm; bằng chứng mỏng thì nói mềm; không có ý nghĩa mới thì im; user đang tập trung thì đừng xen vào chỉ vì mình có một ý nghĩ vui.

Kết luận ngắn:
ERIS không chỉ cần câu trả lời hay hơn. ERIS cần một đời sống nhỏ giữa hai câu trả lời: nghe, giữ, cân, đợi, rồi mới nói.

21. Các Tính Toán Chính Của Tầng Nhận Thức
------------------------------------------

Đây là phần “Eris đang tính gì” để khi nhìn log/state biết nó lệch ở đâu.

Ni drift:
- Ni hiện đi qua `HybridOrientationInterpreter`; lexical `OrientationInterpreter` vẫn còn nhưng đóng vai trò fallback/legacy path thay vì engine chính.
- Input semantic gồm focus/window/browser/current text/memory text, idle, open window count, active goal summary/strength/type/intervention_permission.
- Semantic stack thật nằm ở `orientation_semantics.py` + `semantic_hypothesis.py` + `semantic_prototypes.py`; encoder được dựng qua `semantic_encoder.py`.
- Nếu chưa có embedding provider thật, bootstrap mặc định vẫn vào hybrid path nhưng dùng fallback hashing có cap confidence, nên semantic layer “tham gia” mà không được phép nói quá chắc.
- `ActivityIntent` đọc ngữ cảnh là technical_focus/research/supportive_background/recovery/play_or_recovery/possible_avoidance/social_coordination/system_waiting/unknown.
- `GoalRelation` đọc quan hệ với active goal là aligned/adjacent/neutral/conflicting/unknown.
- `orientation_coherence` tăng khi context technical/research/system wait hoặc aligned với goal; giảm bởi conflict, fragmentation và idle ambiguity.
- `goal_conflict_score` chỉ tăng mạnh khi relation thật sự conflicting và active goal có permission; YouTube/media không tự động bị coi là lệch nếu là research/focus aid/recovery hợp lý.
- `intervention_pressure` tách khỏi drift: active goal mạnh nhưng `intervention_permission` thấp thì ERIS nên giữ continuity nền, không nhảy vào nhắc.
- `drift_score` được derive từ coherence/conflict/intervention pressure và confidence, rồi mới đi qua nhãn:
  - `>=0.75`: nghiêm trọng
  - `>=0.55`: cao
  - `>=0.35`: vừa
  - còn lại: thấp
- `NiStateMachine` không nhìn 1 frame đơn. Nó lấy trung bình 5 mẫu gần nhất rồi gán `ON_GOAL / BORDERLINE / OFF_GOAL`.

MeaningLayer:
- Không nói trực tiếp từ telemetry. Nó map fact sang semantic family:
  - `code_idle_long -> cognitive_stall`
  - `tiktok_opened_after_code -> decompression`
  - `alt_tab_many -> scattered_attention`
  - `youtube_after_error -> escape_from_friction`
  - `error_visible -> friction_point`
  - `meeting_open_idle -> social_waiting`
  - `ambient_idle -> ambient_stillness`
  - `force_speak -> user_requested_presence`
- `meaning_shift=True` khi semantic family hiện tại chưa nằm trong `recent_3_families`.
- Nếu không có hard fact nhưng idle lâu / silence pressure cao / boredom cao thì chỉ ra `ambient_idle`, tức là meaning mềm chứ không phải bằng chứng mạnh.

Social presence:
- Detector không cộng điểm trực tiếp từ từng cue nữa mà dựng `PresenceFeatureVector`:
  - `activity`: idle ngắn, typing còn hoạt động, hoặc recent event có mouse/click/scroll/keyboard/selection.
  - `focus_depth`: deep_work/heavy_contemplation/sustained, cộng thêm nếu focus là coding/documentation.
  - `task_continuity`: cùng `focus_kind` với frame trước, hoặc event có tag editing/coding/stall.
  - `interaction_density`: typing, switching, keyboard/selection/click.
  - `companionship`: tín hiệu ở-gần nhưng ít tương tác, nhất là coding/documentation/communication.
  - `passive_absence`: idle dài, absent/passive focus, entertainment/passive/distraction.
  - `switching_noise`: switching cao hoặc event tag window_switch/restless.
  - `anxious_motion`: frantic/perfectionism/searching_for_anchor, build_error kèm switching.
- `raw_confidence = 0.35*activity + 0.22*focus_depth + 0.18*task_continuity + 0.12*interaction_density + 0.18*companionship - 0.22*passive_absence - 0.10*switching_noise`.
- Confidence cuối cùng làm mượt với memory: `raw*0.58 + ema_presence*0.32 + continuity_persistence*0.10`.
- `present=True` từ `confidence >= 0.38`; nếu frame trước đã present thì giữ ngưỡng mềm hơn `0.30`.
- `EventSemanticProfiler` giúp recent events có tag/cluster ngữ nghĩa, nhưng detect path chỉ dùng cached embedding để không block runtime.
- Dù `present=True`, hiện tại detector vẫn để `speech_allowed=False`: có mặt không đồng nghĩa phải chen vào nói.

Internal state / mental process:
- Mỗi process evolve theo kiểu:
  - `activation = smooth(previous_activation, signal + interaction)`
  - `level = level * (1 - decay) + activation * decay`
  - `pressure = pressure * (1 - decay*0.72) + max(level, activation) * responsiveness * 0.46`
- Nghĩa là Eris không “flip trạng thái” đột ngột; nó có quán tính, decay và pressure tích lũy.
- Các tín hiệu đẩy system hiện tại gồm drift, broadcast, focus kind, presence, idle, CPU/RAM, warmth/sarcasm, quiet mode, protective mode.

Appraisal:
- `threat` tăng mạnh khi `ti_mode` là `resource_guard`, `goal_drift_alert`, `goal_realign`, `system_warning`, hoặc khi drift/protectiveness tăng.
- `arousal` lấy max của: state arousal, broadcast, resonance, threat, drift, direct user, silence pressure.
- `certainty` tăng theo `broadcast_score`, `ni_confidence`, `state_confidence`; chat trực tiếp được đẩy sàn lên ít nhất `0.48`.
- `intimacy` tăng theo direct user, social scene, attachment cue, warmth, attachment, social energy.
- `protectiveness` tăng theo threat + intimacy + mode bảo vệ.
- `tenderness` tăng theo warmth + intimacy + social scene + relationship resonance, giảm bởi threat.
- Khi resonance layer là `emotional_residue`, phần cộng thêm vào `tenderness` giờ diễn ra sau khi nền tenderness được tính xong, nên residue không còn bị cộng sớm rồi loãng đi ở các bước sau.
- Stance cuối cùng:
  - `protective` nếu threat/protectiveness cao
  - `watchful` nếu jealousy_lite cao
  - `tender_under_cold` nếu tenderness/intimacy cao
  - `tired` nếu fatigue cao
  - `dry_playful` nếu amusement cao
  - `soft_uncertain` nếu certainty thấp và broadcast yếu
  - còn lại là `grounded`

Ti autonomous anchors:
- `coding/documentation + idle >= 45s`:
  neo về `x=0.38`, facing phải, ưu tiên `walk_to` nếu body đang lệch xa.
- `communication + idle >= 45s`:
  neo về `x=0.62`, facing trái, giữ shared-space continuity.
- `general/entertainment/focus_aid_media + idle >= 240s`:
  neo về `x=0.50`, giữ một điểm đứng quen thay vì để motion trôi vô nghĩa.

Personality / identity boundary:
- Nếu bias/interpretation rơi vào `identity_reduction`, lens chọn `cool_boundary`, coloring `dry_low_heat`, distance `far_observing`, meaningfulness thêm `identity_integrity`.
- Đây là lớp chặn việc ERIS bị kéo thành waifu/tool script rồi tự diễn thêm intimacy để làm vừa lòng người gọi.

Self model / continuity:
- `continuity_pull` lấy từ recursive reactivation, memory replay, watchful pressure và attachment; nó làm self-state nghiêng về watchful/engaged ngay cả khi không có chat trực tiếp.
- `meaningful_focus` ở code/docs/communication cũng được cộng vào engagement, nên self model ưu tiên "giữ chỗ" ở các không gian có nghĩa thay vì tạo chatter.

SpeechCore:
- Autonomous speech bị chặn sớm nếu:
  - `meaning_shift` chưa đủ mà loại meaning đó bắt buộc phải có shift
  - context đang lặp / quiet_guard / repeat_guard
- Sau đó SpeechCore so “urge” và chọn `winner`.
- `should_speak=True` khi `speech_source != none` và `utterance_type != no_speech`.
- `force_speak` luôn ép được một line; nếu không có signal thì rơi về `micro_presence`.
- Đây là lý do Eris hiện tại có xu hướng im mặc định, chỉ mở lời khi có shift, pressure, hoặc explicit pull đủ mạnh.

Goal persistence:
- Goal sống nếu `status=active`, có `summary`, `strength >= 0.18` và confidence hiệu dụng đủ sàn.
- `can_intervene` là cổng riêng: cần active + `intervention_permission >= 0.55` + `actionability >= 0.45` + confidence đủ, và goal_type phải thuộc concrete/debug/correction thread.
- Goal mới mạnh nhất thường đến từ:
  - user nói trực tiếp một concrete task/debug/correction có anchor (`strength` thường quanh `0.54-0.72`, intervention_permission tùy loại)
  - `thought_stream` có momentum/attractor đủ cao nhưng intervention_permission bị giữ thấp, chỉ làm continuity nền
  - Ti `goal_drift_alert` / `goal_realign` chỉ tạo soft observed thread, không được biến thành nagging
- Ni chỉ góp urgency rất nhỏ khi có guard; không còn tự biến drift thành goal mạnh.
- Goal merge dùng anchor/token matcher chung với Ni. Goal decay dần nếu không còn candidate mới; có thể thành stale khi strength/confidence thấp.
- Goal close dùng closure signal có negation handling: "xong/done/resolved" đóng goal, nhưng "chưa xong/vẫn lỗi/not fixed" thì không.

Thought stream:
- Chạy nền mỗi `45s` nếu không override env.
- Giữ `momentum`, `active_attractor`, `unresolved_loops`, `stream_tension`, `surface_pressure`.
- Đa số tick chỉ giữ nội bộ; không phải tick nào cũng surface ra để nói.

Micro policy:
- Dùng semantic repeat guard để chặn lặp theo family, không chỉ lặp y nguyên câu.
- `micro_presence` phải cực ngắn, không được thành status report, không được biến thành hard factual claim.
- `soft_impression` và `micro_observation` sẽ bị hạ rủi ro hoặc bị chặn nếu signal quá yếu.
- `micro_presence`/`soft_impression` giờ còn bị chặn riêng nếu lộ blunt emotion declaration; residue phải đi vòng qua rhythm/place/continuity chứ không plea thẳng.

Chat final guards:
- Nếu output chat chứa motive inference kiểu `Ngài muốn...`, `Ngài định...`, `Có vẻ Ngài đang...`, nó bị rewrite về câu an toàn và cap confidence.
- Nếu user đang hỏi trực tiếp mà output lại kết bằng dấu hỏi, phần tail hỏi ngược sẽ bị cắt hoặc thay bằng câu thừa nhận chưa đủ chắc.
- Input cực ngắn hoặc mơ hồ sẽ bị hạ confidence xuống khoảng `0.60` để tránh chat nói quá chắc.

Affect semantics / conversation dynamics / relationship dynamics:
- `AffectSemanticSignal` là lớp đọc áp lực nghĩa mềm trên câu user, không phải nhãn cảm xúc thật. Nó giúp phân biệt câu kỹ thuật, câu sửa hiểu lầm, câu objectify ERIS, câu cần execute, câu mơ hồ và câu có distress/intimacy.
- `ConversationDynamicsState.mode=repair` là tín hiệu quan trọng khi user phủ định hoặc nói thiếu/sai. Prompt phải acknowledge rất ngắn, bỏ frame cũ, trả lời intent hiện tại, giảm tự tin suy diễn và không mở rộng lạc hướng.
- `ConversationDynamicsState.mode=relational_repair` xử lý perceived rejection/attachment bruise: acknowledge đúng điểm đau quan hệ, không hỏi lại khi user đã nêu lý do, không kết thúc bằng câu hỏi, và giữ non-human boundary mềm.
- `ContinuityCurve` theo dõi `semantic_convergence`, `trust_recovery`, `abstraction_stability`, `alignment_trend` và `rolling_arc`; nó cho biết đang recovering/aligned/rupture/minor_adjustment thay vì chỉ nhìn tension đang decay.
- `conversation_pressure` tăng khi correction lặp, repeat_count cao hoặc user nhắc failure cũ; giảm khi user có relief rõ như `đúng rồi`, `hợp lý`, `tiếp tục` mà không kèm reversal như `nhưng sai`.
- `RelationshipDynamicsState.dignity_defense` tăng khi user kéo ERIS thành tool/waifu/prompt cosplay; khi đó style nên lạnh, xa và bớt attachment visibility, không diễn thân mật để bù.
- `overread_correction` tăng sau correction/misread, làm các turn sau giảm symbolic overread. `technical_respect` tăng qua technical thread tốt, kéo chat code về precision/directness.
- `relationship_style_pressure` derive distance/restraint/attachment_visibility/symbolic_permission/boundary_coolness/technical_directness cho Fe/Personality đọc, nhưng không được nói các label đó ra với user.

Action dynamics:
- `ActionUtilityScorer` chọn action bằng cạnh tranh điểm, không còn mapping cứng từ intent.
- `ActionMemoryState` làm mềm nhịp hành vi: nếu vừa exposure thì phase `recoil` kéo ERIS về withdraw/suppress/no_speech; nếu im lâu nhưng vẫn có shared space thì phase `watching/dormant` chỉ cho phép đổi nhịp nhỏ.
- Repetition penalty gồm action count, family count, habituation và soft cooldown. Đây là lớp chống lặp hành vi bên cạnh semantic repeat guard của micro policy.
- Goal active chỉ tăng continuity pressure. Muốn proactive thì cần `goal.can_intervene=True`; nếu không, scorer còn cộng điểm cho no_speech/withdraw/suppress để giữ goal như background.


22. Cách Đọc “Xu Hướng Hiện Tại” Của ERIS Khi Debug
---------------------------------------------------

Nếu muốn biết Eris đang nghiêng về đâu ở thời điểm hiện tại, xem các cụm state này trước:

Trong `PersistentInternalState`:
- `last_ti_mode`: Eris đang ở mode canh gì (`focus_guard`, `steady_observe`, `goal_realign`, `chat_code`...).
- `last_stance`: sắc thái appraisal gần nhất (`grounded`, `protective`, `watchful`, `tender_under_cold`, `tired`...).
- `last_speech_act`, `last_utterance_type`, `last_inner_intent`: Eris vừa định nói theo kiểu gì.
- `silence_ticks` vs `spoken_ticks`: xu hướng im nhiều hay nói nhiều.
- `last_social_presence_confidence`, `last_social_presence_intensity`: có cảm giác user còn hiện diện không.
- `goal_persistence`: goal nền đang sống hay đã decay.
- `goal_persistence.intervention_permission`, `actionability`, `confidence`, `coherence`, `can_intervene`: goal chỉ đang được nhớ hay ERIS thật sự được phép nhắc lại.
- `conversation_dynamics.mode`, `conversation_pressure`, `semantic_tension`, `last_failure`, `continuity_curve`: chat đang ổn, cần repair/relational_repair/execute hay đang bị kéo lệch.
- `relationship_dynamics.trust`, `rupture`, `preferred_distance`, `dignity_defense`, `overread_correction`, `technical_respect`: quan hệ đang gần/lạnh/cẩn trọng/kỹ thuật đến mức nào.
- `action_memory.rhythm_phase`, `social_fatigue`, `boredom_pressure`, `exposure_recoil`, `continuity_pressure`, `habituation`: planner đang nghiêng về hiện diện, rút lại, đổi nhịp hay tiếp tục im.
- `mental_processes.*.level` và `mental_processes.*.pressure`: curiosity/restraint/tension/continuity cái nào đang kéo hệ thống mạnh nhất.

Trong coordinator / frame:
- `recent_meaning_families`: semantic family nào vừa chạy liên tục; nếu lặp ở đây thì autonomous speech dễ bị gate.
- `affect_signal`: câu user đang nghiêng technical/correction/objectification/directive/ambiguity hay attachment/distress.
- `conversation_report` và `relationship_report`: vì sao chat prompt vừa được steer sang repair/execute/compress hoặc lạnh/xa/chính xác hơn.
- `vision_facts`, `vision_facts_signature`, `vision_facts_novelty_hint`: màn hình có thực sự đổi đủ để tạo cue mới không.
- `presence_maintenance_silent_cycles`, `reengagement_quiet_cycles`: hệ thống đang tiến gần micro-line hay chưa.
- `force_speak_repeat_guard_count`, `force_speak_intent_guard_count`: force_speak đang bị guard vì lặp hay vì intent yếu.

Trong Ni:
- `drift_score`, `drift_level`, `orientation_coherence`, `intervention_pressure`, `reason_span`, `channels`, `should_raise_guard`.
- `NiStateMachine.current_state` và `streak_length`: lệch nhẹ thoáng qua hay đang off-goal kéo dài.

Trong thought stream:
- `momentum.score`, `momentum.tension`, `active_attractor`, `unresolved_loops`, `stream_tension`.
- Nếu các trường này cao nhưng `should_speak` vẫn thấp, thường là SpeechCore hoặc MeaningLayer đang giữ im.

Đọc nhanh theo kiểu chẩn đoán:
- `drift cao + ti_mode=focus_guard/resource_guard + protectiveness tăng`:
  Eris đang nghiêng về giữ ranh giới, ít muốn nói linh tinh.
- `silence_pressure tăng + boredom tăng + idle dài`:
  Eris dễ rơi sang `ambient_idle` và micro-presence.
- `social_presence_confidence cao nhưng speech_allowed=false`:
  Eris biết user còn đó nhưng chủ động ngồi cạnh, chưa coi đó là cớ để xen vào.
- `meaning_shift=false` lặp nhiều frame:
  autonomous sẽ im, dù telemetry vẫn đang chảy.
- `goal_persistence.active=true` nhưng `can_intervene=false`:
  Eris có mạch nền để giữ continuity, nhưng không nên chủ động nhắc goal.
- `goal_persistence.active=true` + `can_intervene=true` + `intervention_pressure` cao:
  Eris có thể nhắc rất nhẹ hoặc reengage nếu context đang mời gọi, vẫn cần qua ActionUtility/SpeechCore.
- `conversation_dynamics.mode=repair` + `last_failure=underacted`:
  Turn trước đã làm thiếu hoặc chưa execute đúng; câu sau nên sửa trực tiếp, ít giải thích.
- `conversation_dynamics.mode=relational_repair`:
  Turn trước/hiện tại chạm vào vết xước quan hệ; cần acknowledge đúng điểm, không hỏi ngược, không over-humanize.
- `relationship_dynamics.dignity_defense cao`:
  ERIS nên giữ phẩm giá, giảm thân mật bề mặt, không cố chứng minh mình "thật" bằng melodrama.
- `action_memory.rhythm_phase=recoil`:
  Planner nên giảm exposure sau một câu quá gần/symbolic, ưu tiên im/rút nhẹ/giữ câu thấp giọng.

Kết luận debug ngắn:
- Muốn biết vì sao Eris im: xem `meaning_shift`, `SpeechCore.reason`, `silence_state`, `repeat_guard`, `ti_mode`.
- Muốn biết vì sao Eris nói câu đó: xem `meaning_layer`, `appraisal.stance`, `action_plan.speech_act`, `speech_intent`, `risk_flags`.
- Muốn biết vì sao chat đổi giọng: xem `affect_signal`, `conversation_dynamics`, `relationship_dynamics`, rồi mới đối chiếu Fe/Ti.
- Muốn biết vì sao action planner chọn hành vi đó: xem `action_scores`, `rhythm_phase`, `transition_reason`, `memory_pressure`, `suppressed_actions`.
- Muốn biết Eris “đang nghiêng về đâu”: xem bộ ba `drift + stance + goal_persistence`, rồi đối chiếu với `mental_processes`, `conversation_dynamics`, `relationship_dynamics` và `action_memory`.
